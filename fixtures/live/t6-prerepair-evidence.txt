## Which check fails against the pre-repair code

1. **F1 — `minted id for sess-1#0 is not a UUIDv4: b13dca04-670b-55bd-b5b5-b45d62221b30`.**
   The pre-repair `sessionUuidFor` (V1/V5) emits a version-5 UUID; the suite's first session check
   asserts the RFC 4122 v4 shape, and the stand-in then rejects that id exactly like the live CLI
   (`Error: Invalid --new-session-id "…": expected a UUIDv4.`), so `P2` (a bootstrap turn) ends in
   an error finish. V3 passes both.
2. **F2 — `a missing chat store must re-anchor a fresh CLI session`.**
   V4 (repaired id, no store probe) keeps `mode:'resume'`: `P3` shows the second turn resuming the
   deleted chat (`--resume 73d4eac5-…`) with a payload that carries neither the system prompt nor
   the prior turn — the silent context loss t3 proved live. V3 instead mints a new id
   (`--new-session-id 33b04911-eda6-41a6-…`) and re-delivers the full DSH context.
