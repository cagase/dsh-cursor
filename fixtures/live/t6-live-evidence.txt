## Notes on the captured answers

* `resume` returned `PLATYPUS-7731`: the fact came from the CLI's own chat store, which is
  the only channel that carries prior turns for this account.
* `deadResume` (store removed) took the re-anchor path: the argv carries
  `--new-session-id d8e236e5-...` and the positional prompt is the full bootstrap delivery
  (`<dsh_system_prompt>` + `<dsh_conversation_history>` with the fact + `<dsh_user_message>`).
  That path is the criterion's proof. The model's wording for a "codeword" question is
  model-dependent (Grok sometimes answers UNKNOWN even with the context in band, as this run
  shows; an earlier identical run answered PLATYPUS-7731), so the evidence for F2 is the argv
  plus the bootstrap payload, not the answer text.
* The control in section 4 shows why the pre-repair code lost context silently: a raw
  `--resume` for an unknown chat exits 0, prints nothing on stderr, answers without any
  history, and creates that chat under the requested id.
